1 — System Overview

The Bolakaz Licensing system is a central platform that handles software license sales and validation across multiple products. Instead of every client site holding its own Paystack keys and managing its own code generation, they all use this single service.

What It Does

  • Sells license codes for any number of products (Stock-Taking, CRM, POS, etc.)
  • Validates codes when client sites redeem them
  • Prevents fraud — server-computed pricing, amount cross-checking, race-condition protection
  • Requires zero code changes to add a new product — just add it in the admin panel

The Three Roles

RoleWhoWhat They Do
Admin You (Bolakaz owner) Create products, set pricing, generate client credentials, view license codes
Client Site Shop owners / site admins Put the purchase link on their site, call the redeem API when users enter codes
End User Customers of client sites Visit the purchase link, pay via Paystack, receive a license code, enter it on the client site

3.4 — Generating Client Credentials

Navigate to Client Credentials. Each credential grants one client site the ability to redeem codes for one specific product.

⚠️ Critical: The API secret is shown ONLY ONCE. After creating a credential, Filament will display the plaintext secret in a notification. Copy it immediately. It is stored as a bcrypt hash in the database and cannot be recovered later. If lost, you must create a new credential.

  • Success notification: shows the client_key
  • Warning notification: shows the api_secret in plaintext — copy it NOW
Give these two values to the client site owner: 
X-Client-Key:    SHOPNAME_aB3xYz...9fG2

💡 One credential = one product + one client site. If a site uses two products (e.g., Stock-Taking AND CRM), create two separate credentials — one for each product. This way, if a credential is compromised, only one product on one site is affected.

4 — Purchase Flow (for End Users)

4.1 — The Purchase Link

Each product has a single, permanent purchase URL:

https://teslim.unibooks.com.ng/purchase/{product-slug}

Examples:

ProductPurchase URL
Bolakaz Stock-Takinghttps://teslim.unibooks.com.ng/purchase/bolakaz-stocktaking
Bolakaz CRM (future)https://teslim.unibooks.com.ng/purchase/bolakaz-crm

Client sites put this link wherever they want users to buy a license — a "Buy License" button, a paywall page, a pricing card, an email, anywhere.

4.2 — How a User Purchases a License

User visits the purchase link

They see the product name, description, daily rate, and tier options (e.g., 3 Days / 7 Days / 30 Days / Custom). Prices are computed server-side from the tiers you configured in Filament.

User selects a plan and enters their email

For fixed tiers: clicks the tier card. For custom: enters number of days. The total price updates live.

User clicks "Pay with Paystack"

A Paystack popup opens. The user completes payment with card, bank transfer, or USSD. They never leave the page.

Payment confirmed — code appears

The user sees a success page with their license code displayed prominently and a "Copy" button. The code is also emailed to them.

User enters the code on the client site

The client site's backend calls the redemption API to validate the code. If valid, the license is activated for the purchased duration.

🔒 Security note: The price is always computed on the server. The client never sends an amount — the Laravel API calculates it using the product's daily rate and tier configuration. On verification, the amount Paystack confirms is cross-checked against the server-computed amount. If they don't match, no code is issued.

5 — Redemption API (for Client Site Developers)

This section is for the developer who maintains the client site. Give them this section of the manual along with their credentials.

5.1 — How It Works

  1. User enters a license code on the client site (a form or input field)
  2. The client site's backend sends the code to the redemption API
  3. The API responds with valid: true or valid: false
  4. If valid, the client site activates the license for the returned duration
⚠️ Never call this API from frontend JavaScript. Your api_secret would be exposed to anyone who opens DevTools. Always call the redemption API from your server-side code (PHP, Node, Python, etc.).

5.3 — API Response

Success (200 OK)

{
  "valid": true,
  "duration_days": 7
}

Invalid Credentials (401 Unauthorized)

{
  "valid": false,
  "reason": "invalid credentials"
}

Invalid or Already Redeemed Code (422 Unprocessable)

{
  "valid": false,
  "reason": "License code not found, already redeemed, or not valid for this product."
}

Rate Limited (429 Too Many Requests)

More than 5 attempts per minute from the same IP. Wait and retry.

5.4 — Example: PHP / Laravel

<?php

use Illuminate\Support\Facades\Http;

function redeemLicenseCode(string $code, string $domain): array
{
    $response = Http::withHeaders([
        'X-Client-Key'    => env('BOLAKAZ_CLIENT_KEY'),
        'X-Client-Secret' => env('BOLAKAZ_CLIENT_SECRET'),
        'Content-Type'    => 'application/json',
    ])->post('https://api.teslim.unibooks.com.ng/api/redeem-code', [
        'code'   => strtoupper(trim($code)),
        'domain' => $domain,
    ]);

    return $response->json();
}

// ── Usage in a controller ──

public function activateLicense(Request $request)
{
    $request->validate([
        'license_code' => 'required|string|size:19',
    ]);

    $result = redeemLicenseCode(
        $request->input('license_code'),
        $request->getHost(),
    );

    if ($result['valid'] ?? false) {
        $days = $result['duration_days'];
        $expiresAt = now()->addDays($days);

        // Store the license activation in your database
        // License::create([...]);

        return back()->with('success', "License activated for {$days} days!");
    }

    return back()->withErrors([
        'license_code' => $result['reason'] ?? 'Invalid license code.',
    ]);
}

5.5 — Example: Node.js / JavaScript

// Server-side only — never expose BOLAKAZ_CLIENT_SECRET to the browser

const BOLAKAZ_CLIENT_KEY = process.env.BOLAKAZ_CLIENT_KEY;
const BOLAKAZ_CLIENT_SECRET = process.env.BOLAKAZ_CLIENT_SECRET;

async function redeemLicenseCode(code, domain) {
  const response = await fetch(
    'https://api.teslim.unibooks.com.ng/api/redeem-code',
    {
      method: 'POST',
      headers: {
        'X-Client-Key': BOLAKAZ_CLIENT_KEY,
        'X-Client-Secret': BOLAKAZ_CLIENT_SECRET,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        code: code.trim().toUpperCase(),
        domain: domain,
      }),
    },
  );

  return response.json();
}

// ── Usage in an Express route ──

app.post('/activate-license', async (req, res) => {
  const { licenseCode } = req.body;
  const result = await redeemLicenseCode(licenseCode, req.hostname);

  if (result.valid) {
    // Activate the license for result.duration_days
    res.json({ success: true, days: result.duration_days });
  } else {
    res.status(422).json({ success: false, message: result.reason });
  }
});

6 — Adding a New Product (Zero Code Changes)

This is the core design principle: onboarding a brand new product requires no code changes and no deployment. Everything is data-driven.

Create the product in Filament

Admin → Products → New Product. Fill in name, slug, code prefix, daily rate.

Add its price tiers

Admin → Price Tiers → New. For each tier, select the product and set the tier key, duration, and discount.

Generate client credentials for each site

Admin → Client Credentials → New. One credential per (product + client site). Give the client_key and api_secret to the site owner.

Give the site owner the purchase link 
https://teslim.unibooks.com.ng/purchase/{product-slug}

The React app automatically loads the product and its tiers from the API. The purchase page works instantly — no frontend changes needed.

That's it. Four steps. No code. No deploy. The purchase page, tier display, price calculation, Paystack integration, code generation, redemption API, and Filament admin all work for any product you add.

💡 Pro tip: Each product can have a completely different pricing structure. One product might offer 3/7/30-day tiers at ₦2,000/day with discounts, while another offers 14/30/90-day tiers at ₦5,000/day. Configure it in Filament and it just works.

8 — Troubleshooting & FAQ

Common Issues

"The purchase page shows 'Product not found'"

  • Check that the product is_active is ON in Filament
  • Verify the slug in the URL matches exactly (case-sensitive)
  • Check that VITE_API_BASE is set correctly in Vercel and the portfolio was redeployed

"Payment goes through but no code appears"

  • Check the Laravel logs on the VPS: storage/logs/laravel.log
  • Verify the Paystack webhook URL is set correctly in the Paystack dashboard
  • The webhook is the fallback — if the browser callback fails, the webhook should still generate the code

"Redeem API returns 'invalid credentials'"

  • Verify the client_key and api_secret match what was generated
  • Check that the credential's is_active is ON in Filament
  • Remember: the api_secret is shown only once. If lost, create a new credential

"Code redeems successfully but unlocks the wrong product"

This can't happen. The redemption API checks that the code's licensable_product_id matches the credential's licensable_product_id. A Stock-Taking credential can never redeem a CRM code.

FAQ

Can a single client site use multiple products?

Yes. Create one credential per product for that site. They'll have multiple sets of client_key + api_secret — one per product. When redeeming a code, they use the credential that matches the product the code belongs to.

What happens if someone tries to use the same code twice?

The database transaction with lockForUpdate() prevents this. Even if two requests arrive simultaneously for the same code, only one succeeds. The second gets { "valid": false }.

Can I change pricing after codes have been sold?

Yes. Changing a product's daily_rate or a tier's discount_pct only affects future purchases. Existing codes are unaffected. To remove a tier without deleting it, toggle is_active to OFF.

What if Paystack is down?

Users will see a "Payment initialization failed" error. The purchase flow won't proceed. Once Paystack recovers, everything works again. No codes can be lost because codes are only generated after confirmed payment.

Is my api_secret safe?

Yes. It's stored as a bcrypt hash in the database (not plaintext). The middleware uses Hash::check() to verify it — the same secure approach Laravel uses for user passwords. The client_key is a public identifier (like a username) and is stored in plaintext for fast indexed lookup.
